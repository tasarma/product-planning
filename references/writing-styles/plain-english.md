# Writing style: plain English

A lighter style than STE-style. There are no strict word limits. Write so that a busy reader understands the text on the first read.

## Scope
Apply these rules to prose only. Never change code, identifiers, config keys, file paths, log output, quoted text, or user-supplied wording inside quotes.

## Rules
- Keep sentences short. Split a sentence when it has more than one main idea.
- Use the active voice. Say who does what.
- Use common words. Prefer "use" to "utilize" and "start" to "initiate".
- Put the main point first.
- Use the same word for the same thing. Use the terms from the project glossary.
- Use lists for steps and for groups of items.

## Examples
**1. Active voice**
- Before: "The report is generated by the scheduler every night."
- After: "The scheduler generates the report every night."

**2. Common words**
- Before: "Utilize the export functionality in order to facilitate data migration."
- After: "Use the export feature to move your data."

**3. Main point first**
- Before: "Because of a recent change to the rate limits, and after discussion with the team, we will retry failed calls."
- After: "We will retry failed calls. The rate limits changed recently."
